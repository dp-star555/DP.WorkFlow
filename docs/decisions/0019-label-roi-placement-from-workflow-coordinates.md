# ADR-0019：标签 ROI 由流程定位放置，SDK 只对 ROI 取样

状态：Accepted。补充 [ADR-0018](0018-label-inspection-business-node.md)。

## 背景

ADR-0018 把完整标签检测作为独立业务节点，但配方 ROI 仍是相机原图坐标、输入必须与配方同尺寸，SDK 自身只有“假定已对齐/整图平移配准”。做成节点的目的是复用流程已有的模板定位、坐标系等能力；标签移动、旋转后 ROI 应随定位走，而不是在节点内再搬一套定位。

## 决策

- 标签节点新增可选“标签坐标系”（`VisionCoordinateSystem` 绑定）以及标签原点、配方像素尺寸；节点把“配方像素→局部→原图”组合为仿射放置传给 SDK。定位全部由上游节点完成，节点不做模板匹配。
- SDK（DP.LabelInspection）新增 `InspectionPlacement` 与 `InspectionRequest.FromVision(..., placement)`：只对每个 ROI（外扩边距）按放置从原图取样到配方尺寸画布，不变换整张图；ROI 处理代码、规则与报告语义不变，坐标仍为配方坐标。整数平移不插值。
- 选择在 SDK 请求层集中取样，而不是让各 ROI 模块分别支持旋转矩形：改动集中、所有模块（定位、质量、识别、读码、异常）自动受益，且行为与未放置时一致。
- 配置页用同一轮定位把标签区域摆正后作为编辑底图；模板参考图也取自摆正后的标签图。报告显示时按放置换算回原图。
- 未绑定坐标系时保持原整图行为，已有配方不受影响。

## 代价

- ROI 范围的双线性重采样对逐像素差异、清晰度类指标有轻微影响；建议缩放接近 1。
- 已有整图配方接入坐标系后需在标签图上重画 ROI 和参考图。
- ROI 绘制仍在 SDK 工作台中完成；改用通用 ROI 编辑器另行决策。

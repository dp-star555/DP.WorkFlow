# 标签配方版本与本次任务选择

链路相同而配方不同的标签检测，采用单节点绑定本次任务的配方ID/版本，不通过运行中改写冻结节点属性或可变全局“当前配方”切换。保留固定RecipeJson模式；目录模式必须明确选择，未知/空选择故障且不回退固定配方。启动仅读取有界索引，选择在异步加载前固定，ROI、原生规则、准确库修订及参考位姿来自该版本。

发布工具捕获活动参考/模型摘要，先写完整描述、再原子替换轻量索引。同一ID/版本不能改写；已写出的历史/孤立快照也占用版本号。目录刷新是显式宿主操作、失败保留旧目录，不提供文件监听。新任务可选择新版本，在途加载/检测仍使用原版本租约；使用ID@版本避免ID自动选择最高版本带来的业务升级。

复用ADR-0020的两层缓存与容量/租约规则。外部目录内同一完整版本、相同执行预算可复用串行引擎；不同版本/配方的资源、参考位姿与结果不混用，重模型仍按内容共享。预热进入生产同一缓存但不检测、不发布报告、不修改选择；配置页编辑/试检测仍独立。报告带实际配方JSON及ID/版本，目录报告只读展示，不以运行结果覆盖编辑草稿。节点确认不自动发布文件，发布/刷新/预热不随取消编辑回滚。

此方案优先降低上百配方启动与常驻资源成本，接受冷加载等待和容量满额时明确拒绝。数量上限不是字节硬预算；不在本轮增加模型多实例池、资源打包复制或长期报告仓。发布是本地受信配置管理，不代替资产访问控制；旧版本资产/库修订须保持不可变。

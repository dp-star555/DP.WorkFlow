# ADR-0017：视觉绑定引用当前来源，不锁定制作快照

- 状态：Accepted
- 取代：模板与坐标文档中“更换模板或定义后须逐个确认制作身份”的规则；不改变运行帧身份、配置冻结和资源所有权。

## 背景与决策

工程师希望覆盖上游模板后，通过同一个匹配／坐标来源继续运行，下游局部参数不变。把模板参考签名和制作时定义快照作为消费者执行契约，会造成“编译不通过→无法取得新图→无法重做范围”的配置死锁，也把来源内部实现变化泄漏到所有下游。

因此，持久化绑定决定**从哪里取本帧输出**，不保证来源永远使用同一模型或制作定义。原制作ID、版本和签名可留作追踪记录，允许缺省，不参与消费者编译、运行或图上编辑的有效性判断；不自动改写局部数值，不保存或复用运行矩阵。

模板参考的原点、方向与尺度仍决定新映射；资源签名保留在构建来源证据中，不并入工作流业务坐标定义。实际加载、验证并捕获的资源快照是运行依据，制作缓存不是其更新的否决条件。

## 同类约束的处理

- 坐标构建节点独立提供输出；不因同一业务ID的另一个来源名称、版本或单位不同而阻断整图。需要将实际几何事实混合运算时，仍检查同帧与实际映射一致性，或显式转换。
- 模板清单路径可通过文件属性直接更换；制作窗口不是唯一的资源引用入口。
- 算法实现切换时，专属参数、参数版本和下级依赖在同一个编辑事务中重置；不用先人工清空，也不将旧厂商参数冒充通用配置。
- 同一实现可在有限的依赖链中出现多次；循环判断以真实配置对象引用为准，保留深度／编辑预算。
- 当前工厂未声明的依赖分支视为未启用：保留配置但不准备、调用或升级该分支，不因其插件未安装而阻止活动算法。当前声明的必需依赖缺失、重复槽位或接口不匹配仍拒绝。

## 保留与代价

保留来源引用、路径可见性、输入类型、自身绑定、当前帧身份和尺寸、匹配成功与矩阵可逆性、算子所需相似变换、资源内容完整性和模型／引擎兼容性、预算、租约、候选准备提交／回滚以及后台过期结果隔离。显式将已有图上范围换算到另一坐标来源时，仍必须取得同帧真实映射，不能凭空推算。

允许更新来源不等于保证局部参数仍符合工艺意图：原点、方向、单位或标定变化后，工程师在新图上核对和调整范围。版本和签名用于诊断追踪，不作为自动的产品合格判断或更新禁令。必要的生产配方审批应另设明确的发布规则，而不是隐含在节点制作签名中。

## 验证入口

- `VisionCoordinateSourceBindingTests`：资源／定义更换无需预览或重新确认，局部配置与JSON保持，来源丢失、自身绑定、类型不匹配及异帧仍拒绝。
- `VisionCoordinatePipelineTests`、`VisionGeometryPluginPipelineTests`：真实模板替换后的多层定位、ROI、卡尺、几何结果与图上编辑，缺目标不复用旧矩阵。
- `VisionTemplateAuthoringTests`：实际资源优先于过时制作缓存，路径编辑与撤销。
- `VisionAlgorithmDependencyEditingTests`：实现切换的一步撤销、有限重复实现、停用依赖保留、实际引用循环及过期编辑拒绝。
- 独立DP.Vision的`AlgorithmRuntimeTests`、`AlgorithmInspectionTests`：双框架资源准备／共享／生命周期、重复实现、停用依赖和真实循环校验。

# 工程师预设处置分支，运行时执行受验证的恢复出口

状态：accepted（V1范围）。

异常处置属于工位/工艺，而不是故障节点：工程师编写处理子流程，操作员只在预设的少量分支中选择。节点提供原操作的执行与核实能力；运行时区分“继续原操作”和“从命名入口重执行”，保留执行身份，统一处理数据失效和恢复授权。为避免用修改程序指针掩盖设备、副作用和循环/并行状态问题，禁用旧任意Jump，首版只开放受工位验证的无环串行入口重执行。

## 后果

- 默认节点失败和普通异常可进入所属运行的处理策略，不需要报警编号；显式StopRun仍然终止。
- 原操作以独占实例保存意图，每次尝试使用新暂存上下文；不是把运行状态写回NodeModel。
- 命名入口标记不是安全证明，必须由工位Guard核实现场和重执行前提。
- 处理流程自身异常可能发生在处置副作用之后，V1终止而不是自动从头重放。
- 旧Jump文档仍可读取，但运行时拒绝；并行恢复保护不放宽，复杂检查点和外部受控中断后续继续设计。

实现范围与用法见[异常恢复V1](../nodes/fault-recovery-v1.md)，完整目标见[场景草案](../node-recovery-scenarios-design.md)。

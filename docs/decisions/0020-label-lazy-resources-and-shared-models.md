# 标签轻量登记、按需资源与共享模型

后续[ADR-0021](0021-label-task-recipe-selection.md)已在此缓存之上增加任务配方选择；以下保留本阶段范围与取舍。

多配方分支可能包含上百个标签节点，全量准备和每节点独立加载ONNX会使启动时间与常驻内存随配方数增长。运行准备改为事务式轻量登记，详细资源在选中的标签节点首次使用时捕获；配方运行资源与宿主范围内共享模型使用独立、有数量限制的闲置缓存。配方/结果独立，相同内容模型共享；运行登记不持有重资源租约。

选择确定的首次使用延迟和节点级加载故障，换取未使用分支不加载；不声称轻量登记完成模型兼容性验证。暂不修改节点固定配方输入语义，不提供运行时配方目录切换；先兼容现有多分支用法。原型使用共享单实例和完整算法调用串行化，不做无限实例扩容或全进程静态资源。

调用租约保护正在加载、排队及检测的资源；旧版本在途调用必须先退出再释放，并仍占数量名额。默认24小时空闲期限，容量压力提前淘汰闲置资源，全部在用时拒绝新冷加载；共享模型在其它配方仍持有时不得释放。数量上限不等于进程字节硬预算，报告/预览仍需宿主限制保留。

## 离线取图编译异常修复（2026-10-03）

文件/文件夹模式曾在编译时触发“当前图像来源不是相机”。原因是CameraKind作为公开属性，在配置校验和绑定分析的反射扫描中被读取；Browsable(false)与JsonIgnore只影响各自的显示/序列化路径，不阻止这种扫描。虽然扫描会捕获异常，调试器仍可能在抛出位置中断。

相机形态改为显式GetCameraKind()方法，仅由相机预检调用；文件模式不再触发相机专属操作，也没有将离线来源默认解释为相机。新增四来源的配方序列化与编译回归，直接监听首次引发的异常，避免仅验证最终编译成功而漏掉此类问题。视觉节点95项、采集端到端11项、Windows/UI419项，共525项执行通过；两套桌面示例Debug构建均0警告/0错误。

## 固定值与绑定切换修复（2026-10-03）

双平台通用WorkflowInput编辑器曾将所有固定值作为文本提交，导致空字符串或显示文本被转换为ImageFrame等复杂对象；InvalidCastException又不在编辑错误处理范围内。另一个独立问题是旧文本框的迟到失焦事件会将新绑定改回固定值；WinForms的属性结构标识也未包含输入来源，切换后可能仍保留原编辑器。

共享属性模型现在根据输入类型声明是否支持文本固定值：标量、枚举、可空标量、GUID、TimeSpan和单字符串构造的取值对象可编辑，其他对象/数组/字典显示只读类型提示；没有在通用面板中判断ImageFrame或其他视觉类。图像输入请绑定图像获取节点的ImageFrame输出，文件路径应在图像获取节点设置。复杂对象的专用固定值编辑器未在本次新增，已有强类型配置不被文本覆盖。

两平台按编辑器代次、当前节点和输入来源拦截旧控件提交，绑定选择窗口返回时也重新确认目标。WinForms将来源、绑定和固定值状态纳入编辑结构刷新；切到绑定保留原固定值，切回可恢复，仍支持Undo/Redo和配方往返。转换后端提前拒绝不支持的文本目标类型，界面增加InvalidCastException防御处理；没有通过关闭调试器异常设置规避问题。

| 场景 | 操作 | 应看到的结果 |
|---|---|---|
| 原有流程回归 | 默认启动并运行两次 | 正常输出与同帧预览；重跑后资源归还 |

| 引擎缺失 | 移出 dp.vision.zxing 包并重启、打开已保存条码配方 | 节点和原选择保留；ALG_IMPLEMENTATION_MISSING 指向节点，首节点前拒绝运行 |

| 设置错误 | 设置未知字段、不支持的 SettingsVersion、非法范围 | 静态检查列出错误；不会先加载模型再等执行报错 |

| 许可/原生库失效 | 使用实际依赖该环境的引擎 | 准备失败、候选回滚，历史失败可见；修复环境后能重试 |
| 检查取消 | 检查配方资源时点击取消 | 取消与失败区分；不执行节点，不清空上一轮图像；厂商非协作调用可能延后归还 |

| 配置升级 | 对提供迁移规则的引擎点击升级所选节点配置 | 全部槽位成功才提交；撤销/重做有效；失败不改变原配置 |

## 资源配置与 OCR

宿主旁的 algorithm-environment.json 是机器配置，示例：

```json
{ "settingsVersion": 1, "resourceDirectory": "D:\\VisionResources" }
```

模型选择保存在节点/配方中，支持绝对路径、相对于已保存配方的路径，或 resource:Models/recognition.onnx。未保存配方使用普通相对路径会明确报错；机器资源引用禁止越出根目录。配方仍保存原始引用。

OCR 节点的算法配置示例：

```json
{
  "implementationId": "ppocr.recognize",
  "settingsVersion": 1,
  "settings": { "modelPath": "resource:Models/recognition.onnx", "expectedSha256": "" },
  "dependencies": { "preprocessor": { "implementationId": "opencv.text-preprocess", "settingsVersion": 1, "settings": {}, "dependencies": {} } }
}
```

需要使用带内嵌字典、与现有 OnnxTextLineRecognizer 输入输出约定兼容的识别模型。示例不下载/附带真实 OCR 模型。请选择水平单行的原图矩形；界面只允许轴对齐矩形，拒绝 Mask、多形状 ROI 和定位变换。结果保存实际模型 SHA256、识别文字、置信度、原图范围及 CTC 证据，不能据此直接判断印刷质量。

## 嵌套依赖与节点详情窗口复核（2026-10-02）

1. 工具箱加入水平单行 OCR 节点，选中后在算法分组设置 modelPath。普通配置通过文件选择或文本编辑完成，无需手写依赖 JSON。
2. 查看 recognizer 下的预处理依赖：默认明确选择 opencv.text-preprocess；下拉候选只包含当前能力的兼容实现。
3. 双击节点，在详情窗口改变模型路径，然后取消。主节点应保持原路径。再次打开并修改、点击应用；关闭后撤销一次，应恢复整次应用前的算法配置。
4. 将预处理依赖改成“未选择”。原依赖删除，静态诊断应阻止运行；重新明确选择后错误消失。存在私有参数或下级依赖时先开启“清空配置以切换实现”，清空动作也可撤销。
5. 修改有数值范围的专有参数为超限值，提交应失败并保留原值；修正后能够继续编辑。撤销和重做后再次修改应写入当前配方。
6. 用高级依赖配置增加未声明槽位，界面应标注未知槽位并保留全部原始数据。可在该槽位选择“未选择”移除；运行检查会拒绝未修正的未知依赖。
7. 移出引擎包后重启并打开原配方，确认选择和私有配置仍然存在，不能静默换成另一个引擎。恢复包后重启，再检查配方。

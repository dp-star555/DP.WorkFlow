# DP.WorkFlow 多语言框架设计

> 状态：实施中（Phase 1–4 核心闭环完成，业务资源持续接入）  
> 适用范围：`ModernUI.WinForms`、`ModernPropertyGrid.WinForms`、DP.WorkFlow WinForms/WPF 表现层及用户内容生成模块  
> 目标：支持模块化资源管理、运行时语言切换、属性元数据本地化、结构化错误和多人协作。

---

## 当前实施基线

- `ModernUI.Localization` 已实现 TextKey、Catalog、不可变 Snapshot、串行语言切换、失败回滚和 UI SynchronizationContext 发布。
- `ModernUI.WinForms` 已提供 zh-CN/en-US RESX、`ModernLocalizationProvider` 和显式文本不覆盖规则。
- ModernInput、Select、SelectMultiple、InputNumber、DatePicker、Dialog、Validation 和 Accessibility 首批文本已接入。
- `WorkflowDiagnosticsControl` 已作为业务试点，组合 ModernUI 与 workflowUi 模块资源，并保留模型及选择状态。
- Gallery 支持 `--english`；视觉脚本支持 `-IncludeEnglish`。
- PropertyGrid 已提供 `IPropertyPresentationProvider`、独立 RESX、稳定 CategoryKey，并在语言切换后恢复折叠、选择、滚动和编辑焦点。
- 核心命名占位符支持格式说明与大括号转义；资源治理测试会校验语言间 Key 和占位符集合一致。
- `WorkflowRuntimeMonitorControl` 已作为第二个业务试点接入本地化命令、日期筛选、验证、反馈和状态保持；`ApplicationError(Code, Arguments, TraceId)` 已开始承载结构化表现层错误。

## 1. 核心认识

多语言不是单纯替换 UI 控件的 `Text`，而是面向用户内容的统一呈现能力。

需要本地化的内容包括：

- 窗口、按钮、菜单、页签、表头和 Placeholder；
- Tooltip、AccessibleName 和 UI Automation 动作文本；
- 表单校验、业务错误、弹窗和通知；
- PropertyGrid 的属性名称、分类、说明、单位和可选值；
- 邮件、报表、导出、推送和面向用户的 CLI 输出；
- 数字、日期、时间、货币和复数格式。

不应参与本地化控制流程的内容包括：

- 稳定错误代码；
- 属性内部名称和业务标识；
- Exception 类型与 StackTrace；
- TraceId / CorrelationId；
- 结构化技术日志字段。

判断原则：

```text
用户看文本
程序看稳定 Code
运维看结构化日志
```

## 2. 设计目标

1. `ModernUI.WinForms` 保持独立，不依赖 DP.WorkFlow、Vision 或具体应用资源；
2. WinForms 与 WPF 可以复用同一套 Locale、资源快照和错误语义；
3. 每个程序集维护自己的框架文本，每个业务模块维护自己的业务文本；
4. 软件启动后能够安全地切换语言，不出现半中文、半英文状态；
5. 用户输入、选择和页面状态不能因语言切换丢失；
6. PropertyGrid 能够重新翻译、排序、分类和搜索业务属性；
7. 资源缺失、重复 Key 和参数不一致由构建工具自动发现；
8. 调用侧使用小而稳定的 interface，不感知资源加载、缓存和回退细节。

非目标：

- 第一阶段不建设在线翻译平台；
- 第一阶段不要求所有历史页面完全响应式绑定；
- 不让基础控件自动翻译任意业务数据；
- 不根据控件名称或 `Control.Tag` 猜测资源 Key；
- 不把多语言能力合并到 Theme 中。

## 3. 总体构造模型

```text

│ 用户内容调用侧                                           │

└─────────────────────────┬───────────────────────────────┘

┌─────────────────────────▼───────────────────────────────┐
│ Localization Facade / Context                           │
│ 当前快照、模块作用域、Changed 通知                        │
└─────────────────────────┬───────────────────────────────┘
                          │
┌─────────────────────────▼───────────────────────────────┐

└─────────────────────────┬───────────────────────────────┘
                          │
┌─────────────────────────▼───────────────────────────────┐
│ 内部实现                                                  │
│ ResourceStore / Fallback / Formatter / Cache / Reporter │
└─────────────────────────┬───────────────────────────────┘
```

Localization 是一个深模块：调用方只声明“表达什么”，实现内部决定资源从哪里加载、如何回退、如何格式化和缓存。

## 5. 核心 interface

### 5.1 稳定资源 Key

```csharp
public readonly record struct TextKey(
    string Module,
    string Name)
{
    public override string ToString() => $"{Module}.{Name}";
}
```

Key 使用稳定语义，不使用当前显示文本：

```text
modernUi.input.placeholder
modernUi.number.validation.range
propertyGrid.search.placeholder
workflow.editor.action.save
workflow.error.notFound
```

### 5.2 文本目录

```csharp
public interface ITextCatalog
{
    bool TryGetText(
        TextKey key,
        CultureInfo culture,
        out string text);
}
```

### 5.3 只读本地化上下文

```csharp
public interface ILocalizationContext
{
    LocalizationSnapshot Current { get; }

    event EventHandler<LocaleChangedEventArgs> Changed;

    string Text(
        TextKey key,
        IReadOnlyDictionary<string, object>? arguments = null);
}
```

普通控件只消费该 interface，不能主动改变整个应用的语言。

### 5.4 语言管理入口

```csharp
public interface ILocalizationManager
{
    ILocalizationContext Context { get; }

    Task<LocaleChangeResult> ChangeLocaleAsync(
        CultureInfo culture,
        CancellationToken cancellationToken = default);
}
```

### 5.5 不可变快照

```csharp
public sealed record LocalizationSnapshot(
    CultureInfo Culture,
    ITextCatalog TextCatalog,
    TextDirection TextDirection);
```

快照加载完成后一次性替换，保证切换原子性。

## 7. WinForms 页面绑定模型

WinForms 缺少 WPF 风格的动态资源绑定，建议实现 `ModernLocalizationProvider` Extender Provider。

```csharp
[ProvideProperty("TextKey", typeof(Control))]
[ProvideProperty("AccessibleNameKey", typeof(Control))]
[ProvideProperty("AccessibleDescriptionKey", typeof(Control))]
public sealed class ModernLocalizationProvider :
    Component,
    IExtenderProvider
{
    public ILocalizationContext? LocalizationContext { get; set; }
}
```

设计器或代码中的使用形式：

```csharp
localizationProvider.SetTextKey(
    saveButton,
    "workflow.editor.action.save");

localizationProvider.SetAccessibleNameKey(
    clearButton,
    "workflow.editor.action.clear");
```

Provider 负责：

- 监听 `LocalizationContext.Changed`；
- 更新普通 Control、TabPage、ToolStripItem 等对象的用户文本；
- 处理 AccessibleName 和 AccessibleDescription；
- 在 Dispose 时解除订阅；
- 语言切换后统一触发布局。

不推荐把 Key 存放在 `Control.Tag`，因为 Tag 已经可能承担业务用途。

## 8. ModernUI 控件内部本地化

`ModernControl` 只处理框架自己拥有的文本：

```csharp
public abstract class ModernControl : UserControl
{
    public virtual ILocalizationContext LocalizationContext { get; set; }

    protected CultureInfo Culture =>
        LocalizationContext.Current.Culture;

    protected string FrameworkText(
        TextKey key,
        IReadOnlyDictionary<string, object>? arguments = null);

    protected virtual void OnLocalizationChanged()
    {
        PerformLayout();
        Invalidate(true);
    }
}
```

需要优先改造的现有控件：

- `ModernInput`：默认 Placeholder；
- `ModernSelect`：默认 Placeholder、展开/关闭动作；
- `ModernSelectMultiple`：默认 Placeholder、展开/关闭动作；
- `ModernInputNumber`：增加、减少、范围验证提示；
- `ModernRadioButton`：选择、取消选择动作；
- `ModernSegmentedControl`：选择动作。

## 9. 默认文本与显式文本

框架不能在语言切换时覆盖业务方显式设置的文本。

以 Placeholder 为例：

```csharp
private string? _placeholderText;

[DefaultValue(null)]
public string? PlaceholderText
{
    get => _placeholderText;
    set
    {
        _placeholderText = value;
        UpdateEffectivePlaceholder();
    }
}

private string EffectivePlaceholder =>
    _placeholderText ??
    FrameworkText(ModernUiTextKeys.InputPlaceholder);
```

行为：

```text
PlaceholderText == null
    → 使用框架本地化默认值

PlaceholderText != null
    → 使用业务方显式文本，不由框架覆盖
```

如果业务方希望显式文本也动态切换，应通过 `ModernLocalizationProvider` 设置 `PlaceholderKey`，而不是直接写固定文本。

## 10. PropertyGrid 本地化模型

PropertyGrid 不能仅遍历 Label 替换文本，因为属性元数据还参与分类、排序和搜索。

建议建立专用 seam：

```csharp
public interface IPropertyPresentationProvider
{
    PropertyPresentation GetPresentation(
        object owner,
        PropertyDescriptor property,
        CultureInfo culture);

    string FormatValue(
        object owner,
        PropertyDescriptor property,
        object? value,
        CultureInfo culture);
}
```

```csharp
public sealed record PropertyPresentation(
    string PropertyKey,
    string DisplayName,
    string CategoryKey,
    string CategoryText,
    string Description,
    string? Unit);
```

其中：

- `PropertyKey`：稳定属性身份，通常使用 `PropertyDescriptor.Name`；
- `DisplayName`：当前语言下显示名称；
- `CategoryKey`：稳定分类身份；
- `CategoryText`：当前语言下分类名称；
- `Description`：当前语言下说明；
- `Unit`：本地化后的单位或符号。

### 10.1 稳定分类身份

不能使用翻译后的分类名保存展开状态：

```text
CategoryKey  = acquisition
CategoryText = 采集参数 / Acquisition
```

折叠状态保存 `CategoryKey`，显示使用 `CategoryText`。

### 10.2 PropertyGrid 切换语言

语言变化时需要：

```text
捕获页面状态
→ 重新获取 PropertyPresentation
→ 重新排序、分类和搜索
→ 重建行与 AccessibleName
→ 恢复折叠、选择、滚动和焦点
```

需要保存：

- 搜索文本；
- 当前属性稳定名称；
- 分类折叠状态；
- 滚动位置；
- 标签列宽；
- 可恢复的编辑焦点。

## 11. Enum、选项和业务数据

基础 `ModernSelect` 不自动翻译业务对象或枚举名称。

业务层应提供稳定值和本地化显示文本：

```csharp
public sealed record SelectionOption(
    object Value,
    string Text);
```

```csharp
select.DisplayMember = nameof(SelectionOption.Text);
select.ValueMember = nameof(SelectionOption.Value);
```

语言切换后重新生成 `Text`，但继续使用稳定的 `Value` 恢复选择。

需要区分：

```text
系统呈现文本 → 可以本地化
用户输入和业务数据 → 保持原值
```

例如工作流名称、备注、脚本正文、设备编号不应在语言切换时被修改。

## 12. Culture 与格式化

框架代码不应到处分散读取 `CultureInfo.CurrentCulture`，而应显式使用：

```csharp
LocalizationContext.Current.Culture
```

需要改造的行为：

- `ModernInputNumber` 的显示和解析；
- PropertyGrid 的排序、搜索和 TypeConverter；
- 数字、日期、时间和货币格式；
- 多选值显示；
- 当前语言下的字符串比较。

应用组合根可以为第三方控件兼容而同步 UI 线程的：

```csharp
CultureInfo.CurrentCulture
CultureInfo.CurrentUICulture
```

但 ModernUI 自身应优先依赖显式上下文，避免后台任务和异步流程读取到错误语言。

## 13. 运行时语言切换

推荐流程：

```text
用户选择目标语言
        ↓
异步加载目标语言资源
        ↓
校验资源和格式参数
        ↓
构造不可变 LocalizationSnapshot
        ↓
原子替换当前快照
        ↓
发布 LocaleChanged
        ↓
更新控件内部文本
        ↓
ModernLocalizationProvider 更新页面绑定
        ↓
PropertyGrid 等结构化控件重建并恢复状态
        ↓
PerformLayout + Invalidate
        ↓
持久化用户语言偏好
```

切换必须满足事务语义：

- 资源完整加载前不改变当前 Locale；
- 加载失败继续使用旧快照；
- 同一时间只允许一个切换操作；
- 事件在 UI 线程处理；
- 切换过程中避免显示半更新界面。

WinForms 根窗口可使用：

```csharp
SuspendLayout();
try
{
    await localizationManager.ChangeLocaleAsync(culture);
    PerformLayout();
    Invalidate(true);
}
finally
{
    ResumeLayout(true);
}
```

## 14. 错误和异常本地化

业务层不产生最终翻译字符串，而是产生结构化错误：

```csharp
public sealed record ApplicationError(
    string Code,
    IReadOnlyDictionary<string, object>? Arguments = null,
    string? TraceId = null);
```

示例：

```csharp
return new ApplicationError(
    "workflow.error.notFound",
    new Dictionary<string, object>
    {
        ["workflowId"] = workflowId
    });
```

表现层展示时翻译：

```csharp
var message = localization.Text(
    new TextKey("workflow", error.Code),
    error.Arguments);
```

技术异常链：

```text
Exception + StackTrace
        ├── 写入结构化日志
        ├── 生成 TraceId
        └── 映射安全 ErrorCode
                    ↓
             表现层本地化
                    ↓
              用户可见提示
```

程序不能根据翻译后的 `Message` 判断逻辑。

## 15. 前后端错误协议

推荐响应：

```json
{
  "code": "workflow.notFound",
  "arguments": {
    "workflowId": "WF-1001"
  },
  "traceId": "7A92F1",
  "message": "找不到工作流 WF-1001"
}
```

含义：

- `code`：稳定机器语义；
- `arguments`：本地化参数；
- `traceId`：技术定位；
- `message`：可选的当前语言默认文本。

客户端只能根据 `code` 判断逻辑。

## 16. 构建和资源治理

CI 至少检查：

1. 默认语言资源是否存在；
2. RESX、JSON 或消息格式是否可解析；
3. Key 是否重复；
4. 目标语言是否缺少 Key；
5. `{name}` 等参数是否跨语言一致；
6. 代码引用的 Key 是否存在；
7. 是否存在长期未使用 Key；
8. 是否存在运行时用户文本硬编码；
9. 模块是否越权使用其他模块私有 Key。

推荐门禁：

```text
格式错误、默认语言缺失、重复 Key、参数不一致
    → 阻断构建

目标语言暂时缺失
    → 根据版本阶段告警或阻断
```

设计器 `[Description]` 和 `[Category]` 通常面向开发者，可先排除在运行时硬编码检查之外；业务对象在 PropertyGrid 中展示的元数据仍需要本地化。

## 18. 测试策略

### 18.1 核心逻辑测试

- 语言回退链；
- 参数格式化；
- 不可变快照切换；
- 切换失败回滚；
- 缺失 Key 报告；
- 并发切换串行化。

### 18.2 WinForms STA 测试

- 默认 Placeholder 随语言更新；
- 显式 Placeholder 不被覆盖；
- Extender Provider 更新普通控件；
- 数字输入按目标 Culture 解析；
- AccessibleName 和 DefaultAction 更新；
- Dispose 后解除事件订阅。

### 18.3 PropertyGrid 测试

- 属性名称、分类和说明切换；
- 分类翻译后折叠状态不丢失；
- 搜索按当前语言重新执行；
- 当前选择和滚动位置恢复；
- Enum 显示文本更新但业务值不变；
- 验证错误使用当前语言和正确参数。

测试不应通过当前翻译字符串查找控件，而应使用稳定身份、类型或测试专用标识。

- 显式 Culture；
- 语言切换状态保持重建；
- Enum 和 StandardValues 本地化。

### Phase 5：错误模型与业务接入

实现：

- `ApplicationError`；
- Code + Args + TraceId；
- DP.WorkFlow 和 Vision 错误资源；
- Dialog/Notification 翻译；
- 前后端错误协议。

### Phase 6：治理与高级能力

实现：

- CI 资源校验；

- 强类型 Key 生成；

## 20. 需要避免的反模式

- 每个控件自己读取 RESX 或 JSON；
- 遍历控件名称猜测资源 Key；
- 使用 `Control.Tag` 作为统一语言 Key 存储；
- 把 Localization 塞进 Theme；
- 使用一个全局可变语言对象解决所有窗口；
- 所有代码隐式依赖 `CultureInfo.CurrentCulture`；
- 语言切换时覆盖用户输入和显式业务文本；
- 使用翻译后的分类名、错误信息或选项文本作为稳定身份；
- 在业务层直接生成翻译后的 Exception Message；
- 根据错误 Message 判断业务逻辑；
- 为每一个类型建立没有真实变化需求的浅 interface。

## 21. 最终决策摘要

推荐采用以下组合：

```text
平台中立核心
    ModernUI.Localization

框架内部文本
    每个程序集自己的 RESX

WinForms 页面文本
    ModernLocalizationProvider Extender Provider

ModernUI 内部文本
    ILocalizationContext + 可本地化默认值

PropertyGrid 业务元数据
    IPropertyPresentationProvider

运行时切换
    不可变 LocalizationSnapshot + Changed 通知

Culture 格式化
    显式使用 LocalizationContext.Current.Culture

错误提示
    ErrorCode + Arguments + TraceId，表现层翻译
```

最关键的两个扩展 seam：

1. 普通 WinForms 页面使用 `ModernLocalizationProvider`；
2. PropertyGrid 使用 `IPropertyPresentationProvider`。

最终目标：

> 开发者声明稳定的语义 Key 和参数；框架根据当前 Locale、Culture 和呈现渠道生成最终用户内容，并在运行时切换语言时安全刷新已有界面。

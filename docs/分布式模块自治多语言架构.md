# DP.WorkFlow 分布式模块自治多语言架构

> 状态：目标架构方案  
> 适用范围：`ModernUI.WinForms`、`DP.WorkFlow.UI.WinForms`、Vision/Motion/Script 等功能模块，以及后续插件式 UI 模块  
> 核心目标：功能交给谁开发，对应 UI、资源、翻译和模块校验就由谁负责；主程序只统一控制语言、调用模块并检查模块是否满足发布要求。

---

## 1. 问题定义

本文中的“分布式”不是微服务或远程配置中心，而是**程序集与功能模块自治**：

```text
ModernUI.WinForms.dll
    自己拥有框架控件资源

DP.WorkFlow.UI.WinForms.dll
    自己拥有 DP.WorkFlow UI 资源

DP.WorkFlow.Vision.UI.WinForms.dll
    自己拥有 Vision UI 资源

Vendor.Camera.UI.dll
    自己拥有插件 UI 资源
```

每个模块独立负责：

- 模块内部的资源 Key；
- 默认语言和目标语言 RESX；
- 模块自己的 `ResourceManager`；
- 语言变化后的 UI 刷新；
- 模块错误和校验信息的本地化；
- 模块资源闭包测试；
- 模块卫星程序集的正确发布。

主程序不维护各模块内部 Key，也不建立包含所有文本的中央字典。主程序只负责：

- 当前界面语言；
- 语言切换命令和通知；
- UI 线程调度；
- 用户语言偏好；
- 模块发现和初始化；
- 检查模块是否支持正式发布语言；
- 检查卫星资源是否进入最终发布目录。

一句话概括：

> **主程序拥有语言控制权，功能模块拥有文本解释权和界面刷新责任。**

## 2. 核心设计原则

### 2.1 资源所有权分布，语言状态统一

```text
统一管理：
├── 当前 Culture
├── TextDirection
├── CultureChanged 通知
├── UI Dispatcher
└── 用户语言设置

模块自治：
├── RESX 和卫星程序集
├── ResourceManager
├── 模块资源 Key
├── 页面和控件文本刷新
├── 业务错误文本
└── 模块资源校验
```

### 2.2 主程序不理解模块内部资源

主程序不应出现：

```csharp
WorkflowUiTextKeys.Save
VisionUiTextKeys.InvalidRoi
CameraUiTextKeys.ConnectFailed
```

这些 Key 只能由拥有它们的模块使用。

主程序只面对模块级能力：

```csharp
module.Initialize(context);
releaseChecker.Check(module.LocalizationManifest);
```

### 2.3 程序逻辑不能依赖翻译文本

机器语义使用：

```text
错误类型
错误代码
业务枚举
稳定模块 ID
属性内部名称
```

最终用户文本由拥有语义的模块根据当前 Culture 生成。

### 2.4 运行时切换不等于重新加载资源 DLL

卫星程序集是被动资源。语言切换时无需重新加载 DLL，只需：

```text
更新统一 CultureContext
→ 发布 Changed
→ 各模块使用新 Culture 查询自己的 ResourceManager
→ 更新已创建的 UI
```

## 3. 总体架构

```text
                           主程序
┌────────────────────────────────────────────────────┐
│ UiCultureManager                                   │
│ 当前 Culture · 切换命令 · UI 调度 · 用户偏好       │
│                                                    │
│ ModuleRegistry / ModuleReleaseChecker              │
│ 模块加载 · 版本兼容 · 发布语言完整性检查            │
└────────────────────────┬───────────────────────────┘
                         │ 同一个 IUiCultureContext
           ┌─────────────┼──────────────┐
           ▼             ▼              ▼
┌─────────────────┐ ┌──────────────┐ ┌──────────────────┐
│ ModernUI.dll    │ │ DP.WorkFlow.dll │ │ VisionUI.dll     │
│                 │ │              │ │                  │
│ ModernUiStrings │ │ DP.WorkFlow...  │ │ VisionUiStrings  │
│ ResourceManager │ │ ResourceMgr  │ │ ResourceManager  │
│ 自己刷新控件     │ │ 自己刷新页面 │ │ 自己刷新页面      │
└────────┬────────┘ └──────┬───────┘ └────────┬─────────┘
         │                 │                  │
         ▼                 ▼                  ▼
 en-US/ModernUI     en-US/DP.WorkFlow      en-US/VisionUI
 .resources.dll     .resources.dll      .resources.dll
```

这里不存在运行时全局 `CompositeTextCatalog`。每个模块通过自己的资源类型和程序集定位自己的卫星资源。

## 5. 共享语言契约

分布式自治模式下，共享模块只管理语言状态，不提供全局文本查询。

### 5.1 语言快照

```csharp
public sealed record UiCultureSnapshot(
    CultureInfo Culture,
    TextDirection TextDirection,
    long Revision);
```

### 5.2 只读语言上下文

```csharp
public interface IUiCultureContext
{
    UiCultureSnapshot Current { get; }

    event EventHandler<UiCultureChangedEventArgs> Changed;
}
```

### 5.3 语言管理入口

```csharp
public interface IUiCultureManager
{
    IUiCultureContext Context { get; }

    Task ChangeCultureAsync(
        CultureInfo culture,
        CancellationToken cancellationToken = default);
}
```

### 5.4 该契约不负责什么

`IUiCultureContext` 不提供：

```csharp
string Text(TextKey key);
```

原因是文本解释权属于对应功能模块。共享 Context 只回答：

```text
当前是什么语言？
文本方向是什么？
语言是否刚刚变化？
```

## 6. 主程序统一触发语言切换

主程序只创建一个 `UiCultureManager`：

```csharp
using var cultureManager = new UiCultureManager(
    initialCulture,
    winFormsDispatcher);

Application.Run(new MainForm(
    cultureManager.Context));
```

用户选择英语：

```csharp
await cultureManager.ChangeCultureAsync(
    CultureInfo.GetCultureInfo("en-US"));
```

推荐切换过程：

```text
用户选择 en-US
        ↓
UiCultureManager 验证目标 Culture
        ↓
在 UI Dispatcher 上更新快照
        ↓
可选：同步 CurrentCulture / CurrentUICulture
        ↓
发布 CultureChanged
        ↓
所有模块收到同一个通知
        ↓
各模块查询自己的 ResourceManager
        ↓
更新自己的 UI 和格式化内容
        ↓
主程序持久化用户语言偏好
```

如果一个进程只允许一种界面语言，可同步：

```csharp
CultureInfo.CurrentCulture = culture;
CultureInfo.CurrentUICulture = culture;
CultureInfo.DefaultThreadCurrentCulture = culture;
CultureInfo.DefaultThreadCurrentUICulture = culture;
```

模块内部仍建议把 `CultureInfo` 显式传给 `ResourceManager.GetString`，避免异步和后台线程读取错误的线程 Culture。

## 7. 模块自己的资源访问器

Vision 模块示例：

```csharp
internal static class VisionUiTexts
{
    private static readonly ResourceManager Resources = new(
        "DP.WorkFlow.Vision.UI.WinForms.Localization.VisionUiStrings",
        typeof(VisionUiTexts).Assembly);

    public static string Get(
        string key,
        CultureInfo culture)
    {
        return Resources.GetString(key, culture)
            ?? Resources.GetString(
                key,
                CultureInfo.InvariantCulture)
            ?? $"⟦visionUi.{key}⟧";
    }
}
```

更推荐为带参数消息提供强类型方法：

```csharp
public static string InvalidRoi(
    CultureInfo culture,
    string reason)
{
    var template = Get("InvalidRoi", culture);

    return LocalizationTemplate.Format(
        template,
        culture,
        new Dictionary<string, object?>
        {
            ["reason"] = reason
        });
}
```

资源：

```xml
<!-- VisionUiStrings.resx -->
<data name="InvalidRoi">
  <value>ROI 无效：{reason}</value>
</data>
```

```xml
<!-- VisionUiStrings.en-US.resx -->
<data name="InvalidRoi">
  <value>Invalid ROI: {reason}</value>
</data>
```

主程序不需要知道 `InvalidRoi` 的存在。

## 8. 模块响应语言变化

模块控件接受统一 `IUiCultureContext`：

```csharp
public sealed class VisionSettingsControl : UserControl
{
    private IUiCultureContext? _cultureContext;

    public IUiCultureContext CultureContext
    {
        get => _cultureContext
            ?? throw new InvalidOperationException(
                "CultureContext has not been configured.");
        set
        {
            ArgumentNullException.ThrowIfNull(value);

            if (ReferenceEquals(_cultureContext, value))
                return;

            if (_cultureContext is not null)
                _cultureContext.Changed -= OnCultureChanged;

            _cultureContext = value;
            _cultureContext.Changed += OnCultureChanged;

            RefreshLocalization();
        }
    }

    private void OnCultureChanged(
        object? sender,
        UiCultureChangedEventArgs eventArgs)
    {
        if (InvokeRequired)
        {
            BeginInvoke(RefreshLocalization);
            return;
        }

        RefreshLocalization();
    }

    private void RefreshLocalization()
    {
        var culture = CultureContext.Current.Culture;

        titleLabel.Text =
            VisionUiTexts.Get("SettingsTitle", culture);

        exposureLabel.Text =
            VisionUiTexts.Get("Exposure", culture);

        saveButton.Text =
            VisionUiTexts.Get("Save", culture);

        RightToLeft = CultureContext.Current.TextDirection
            == TextDirection.RightToLeft
                ? RightToLeft.Yes
                : RightToLeft.No;

        PerformLayout();
        Invalidate(true);
    }

    protected override void Dispose(bool disposing)
    {
        if (disposing && _cultureContext is not null)
            _cultureContext.Changed -= OnCultureChanged;

        base.Dispose(disposing);
    }
}
```

模块必须自己保证：

- 解除旧 Context 订阅；
- Dispose 时解除事件；
- 事件切回 UI 线程；
- 刷新系统文本但不修改用户输入；
- 文本变化后重新布局；
- Accessibility 和 RTL 同步更新。

## 9. 三类 UI 文本的责任边界

### 9.1 通用控件内部文本

例如：

```text
确定
取消
请选择
增加
减少
展开
关闭
```

归 `ModernUI.WinForms` 所有，由现代控件自己查询 `ModernUiStrings`。

调用业务模块不应重复定义这些控件内部文案。

### 9.2 功能模块业务文本

例如：

```text
删除 ROI
导出运行轨迹
连接相机失败
工作流编译失败
```

分别归 Vision、DP.WorkFlow、Camera 等业务模块。

### 9.3 用户业务数据

例如：

```text
工作流名称
设备编号
用户备注
脚本正文
路径
运行输出
```

这些不是资源文本，语言切换时不得修改。

## 10. 普通 WinForms 页面如何绑定

模块可以提供自己的页面本地化 Provider：

```csharp
public sealed class ModuleLocalizationProvider : Component
{
    public required IUiCultureContext CultureContext { get; init; }

    public required IModuleTextLocalizer Localizer { get; init; }
}
```

DP.WorkFlow 页面：

```csharp
provider.CultureContext = applicationCultureContext;
provider.Localizer = WorkflowUiLocalizer.Instance;

provider.BindText(saveButton, "Save");
provider.BindText(exportButton, "Export");
provider.BindText(runtimeTab, "RuntimeTab");
```

Vision 页面使用相同 Provider 类型，但注入自己的：

```csharp
provider.Localizer = VisionUiLocalizer.Instance;
```

Provider 负责普通：

- `Label`；
- `Button`；
- `TabPage`；
- `ColumnHeader`；
- `ToolStripItem`；
- Placeholder；
- AccessibleName；
- AccessibleDescription。

模块的资源访问器仍然只访问本模块 `ResourceManager`。

## 11. 复杂控件的本地化

不能把所有 UI 都简化为遍历控件并修改 `Text`。

### 11.1 PropertyGrid

属性文本参与：

- 分类；
- 排序；
- 搜索；
- 属性名称；
- 描述；
- 单位；
- 枚举显示。

因此继续使用：

```text
IPropertyPresentationProvider
```

语言变化时：

```text
保存稳定状态
→ 重新生成 PropertyPresentation
→ 重新分类、排序和搜索
→ 重建呈现
→ 恢复选择、折叠、滚动和焦点
```

PropertyGrid 的内部 UI 文本归 PropertyGrid 模块，业务属性文本归提供该业务模型的功能模块。

### 11.2 Enum 和选项

基础控件不能自动翻译任意业务枚举。模块应提供：

```csharp
public sealed record SelectionOption(
    object Value,
    string Text);
```

语言变化后更新 `Text`，使用稳定 `Value` 恢复选择。

## 12. 业务错误的模块所有权

模块产生结构化错误：

```csharp
public sealed record ApplicationError(
    string Code,
    IReadOnlyDictionary<string, object?>? Arguments = null,
    string? TraceId = null);
```

Vision 模块错误示例：

```text
Code = InvalidRoi
Arguments = { reason }
```

Vision 模块负责解析自己的错误：

```csharp
public interface IUserMessageResolver
{
    string Resolve(
        ApplicationError error,
        CultureInfo culture);
}
```

主程序只调用：

```csharp
var message = module.UserMessages.Resolve(
    error,
    cultureContext.Current.Culture);
```

主程序不根据模块错误码访问模块资源 Key，也不比较翻译后的 `Message`。

技术异常仍记录：

```text
Exception
StackTrace
ErrorCode
TraceId
```

最终用户文本由模块 Resolver 安全生成。

## 13. 模块级本地化清单

主程序不检查模块内部每一个 Key，只读取模块构建时生成的能力摘要。

```csharp
public sealed record ModuleLocalizationManifest(
    string ModuleId,
    string NeutralCulture,
    IReadOnlySet<string> SupportedCultures,
    int KeyCount,
    string ContractHash,
    bool IsComplete);
```

模块接口：

```csharp
public interface IUiFeatureModule
{
    string ModuleId { get; }

    ModuleLocalizationManifest LocalizationManifest { get; }

    IUserMessageResolver UserMessages { get; }

    void Initialize(UiModuleContext context);
}
```

模块实现：

```csharp
public sealed class VisionUiModule : IUiFeatureModule
{
    public string ModuleId => "visionUi";

    public ModuleLocalizationManifest LocalizationManifest =>
        GeneratedVisionLocalizationManifest.Instance;

    public IUserMessageResolver UserMessages =>
        VisionUserMessageResolver.Instance;

    public void Initialize(UiModuleContext context)
    {
        // 注册 Vision 页面、PropertyGrid Provider 和相关功能。
    }
}
```

清单应由构建工具生成，不能由模块负责人手工维护 KeyCount、Hash 或完成状态。

## 14. 两级校验模型

### 14.1 模块级详细校验

由功能模块和模块负责人处理：

```text
VisionUiStrings.resx
        ↕
VisionUiStrings.en-US.resx
        ↕
VisionUiStrings.ja-JP.resx
```

检查：

- 基准资源是否存在；
- Key 是否缺失或多余；
- 模板是否合法；
- `{reason}` 等参数是否一致；
- 翻译是否 Missing 或 Stale；
- 是否存在疑似用户文本硬编码；
- 语言切换后 UI 是否刷新；
- 用户输入和选择状态是否保持；
- 卫星程序集是否正确生成。

命令示例：

```powershell
dotnet localization validate \
  --project DP.WorkFlow.Vision.UI.WinForms
```

详细错误由模块团队处理：

```text
visionUi.InvalidRoi
Expected placeholders: reason
Actual placeholders: message
```

### 14.2 应用级集成检查

主程序或 Release CI 只检查：

- 模块是否存在；
- 模块版本是否兼容；
- 模块是否支持全部 `releaseLocales`；
- 模块自身校验结果是否通过；
- 卫星程序集是否进入最终发布目录；
- 必需模块是否完整。

报告示例：

```text
modernUi
  zh-CN ✓
  en-US ✓

workflowUi
  zh-CN ✓
  en-US ✓

visionUi
  zh-CN ✓
  en-US ✗  Module localization validation failed
```

主程序无需知道 Vision 缺少哪些 Key；详细报告由 Vision 模块产物提供。

## 15. 模块负责人交付标准

某个功能模块交给开发人员后，其完成定义应包括：

```text
功能实现
+ UI 实现
+ 基准语言资源
+ 正式发布语言翻译
+ 占位符契约
+ 运行时切换实现
+ 模块本地化测试
+ 生成的模块本地化清单
```

模块 PR 至少应通过：

```text
资源闭包测试
模板和参数测试
UI 语言切换测试
卫星程序集生成测试
伪本地化或长文本视觉检查
```

主程序团队只审核模块契约和集成结果，不接管模块内部翻译正文。

## 16. 插件模块

插件目录示例：

```text
plugins/
└── Vendor.Camera/
    ├── Vendor.Camera.UI.dll
    ├── en-US/
    │   └── Vendor.Camera.UI.resources.dll
    └── ja-JP/
        └── Vendor.Camera.UI.resources.dll
```

插件加载流程：

```text
加载插件程序集
        ↓
获得 IUiFeatureModule
        ↓
读取 ModuleLocalizationManifest
        ↓
检查 releaseLocales 和版本兼容性
        ↓
传入统一 IUiCultureContext
        ↓
初始化插件 UI
```

插件仍然自己访问自己的 `ResourceManager`。

如果使用自定义 `AssemblyLoadContext`，插件加载器必须支持解析 Culture 子目录中的卫星程序集。

## 17. 一个 Manager 还是多个 Manager

### 17.1 普通产品模式

```text
一个进程
一个当前用户
一种界面语言
```

使用：

```text
一个 UiCultureManager
一个共享 IUiCultureContext
```

### 17.2 多语言窗口模式

如果将来需要：

```text
窗口 A：zh-CN
窗口 B：en-US
```

可以显式创建两个 `IUiCultureContext`。模块查询资源时始终使用传入 Context 的 Culture，而不能只依赖全局 `CurrentUICulture`。

这属于特殊产品需求，不应让每个控件自行创建 Manager。

## 18. 与当前 DP.WorkFlow 的关系

### 18.1 建议保留

```text
LocalizationTemplate
TextDirection
语言切换事件机制
UI Dispatcher 抽象
ModernControl 的本地化刷新能力
ModernLocalizationProvider 的绑定思想
PropertyGrid 的 IPropertyPresentationProvider
RESX + ResourceManager + 卫星程序集
```

### 18.2 建议调整

```text
当前 ILocalizationContext
    Culture + 全局 Catalog + Text(Key)

调整为
    纯 IUiCultureContext
```

```text
当前各模块 CreateManager()

调整为
    主程序唯一 UiCultureManager
```

```text
当前全局 CompositeTextCatalog

调整为
    各模块直接使用自己的 ResourceManager
```

```text
当前 ModernLocalizationProvider

调整为
    IUiCultureContext + 当前模块 IModuleTextLocalizer
```

```text
当前模块内部默认运行时 Manager

调整为
    设计时 FixedContext；运行时由宿主注入共享 Context
```

### 18.3 不需要做的事情

在该模式下暂时不需要：

- 主程序统一登记所有资源 Key；
- 运行时扫描所有资源程序集；
- 运行时建立包含全部文本的中央字典；
- 为普通程序集资源引入 `module.json/catalog.json`；
- 外部 JSON 语言目录；
- 远程语言包服务。

这些能力只有在语言包需要脱离模块程序集独立发布时再引入。

## 21. 最终决策摘要

目标架构为：

```text
资源归属：
    各功能程序集自治

资源存储：
    每个程序集自己的 RESX 和卫星程序集

文本查询：
    各模块自己的 ResourceManager

语言控制：
    主程序唯一 UiCultureManager

切换通知：
    所有模块共享 IUiCultureContext

UI 刷新：
    各模块自行响应 CultureChanged

模块验收：
    模块详细校验 + 应用聚合检查

主程序职责：
    调用、切换、检查，不维护模块内部 Key
```

最终调用链：

```text
主程序：
    ChangeCultureAsync("en-US")

统一 Context：
    发布 CultureChanged

各功能模块：
    使用新 Culture 查询自己的 ResourceManager
    → 更新自己的 UI

主程序：
    Check(module.LocalizationManifest)
    → 判断模块是否满足发布要求
```

这套模型实现了真正的功能模块自治：

> **功能交给谁，UI、资源、翻译、刷新和模块校验就归谁；主程序只统一语言状态，并在集成和发布阶段验收模块。**
